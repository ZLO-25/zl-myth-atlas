# 眾神星圖：擴充到「八九成認識」計畫（2026-11-16）

## 目標

ZL 的要求：三套神話的資訊太少，中華尤其簡陋。讀完網站的人，要對希臘羅馬、北歐、中華神話各有八九成的認識。

「八九成」的定義：一般介紹書、博物館導覽、電影遊戲、廟裡會遇到的名字與故事，十個裡有八九個在本站查得到，而且知道出自哪本書。

```
現在                      目標
希臘羅馬  45 張   ──►   約 84 張（+39）
北歐      15 張   ──►   約 43 張（+28）
中華      32 張   ──►   約 87 張（+55）
合計      92 張   ──►   約 214 張
```

做法分三波：

```
第 1 波  新卡片（本檔的清單）          ← 分 13 批，Sonnet 5.5 寫，Fable 驗收
第 2 波  舊卡片加深（92 張，中華優先）
第 3 波  總覽、對照表、測驗、今日影子、Grok 提示詞檔跟著更新
```

## 執行者共同守則（每個 Sonnet 子代理都要照做）

你在自己的 git worktree 裡工作（路徑與分支在任務訊息裡）。先讀 `docs/card-fields.md`，再讀 2 張同體系的現有卡片當範本（中華：`cards/god/god-xihe.md`、`cards/story/story-yu-flood.md`；北歐：`cards/story/story-thor-bride.md`、`cards/god/god-odin.md`；希臘羅馬：`cards/hero/hero-heracles.md`、`cards/story/story-pandora.md`）。

### 1. 內容必須查證，不可杜撰（最重要）

- 沙箱的 `curl` 幾乎連不到任何網站，查資料一律用 **WebFetch**（必要時 WebSearch）。開工第一步先用 WebFetch 試抓一個來源；如果你根本沒有 WebFetch 工具，立刻停止並回報，不要憑記憶寫卡。
- 卡片裡每一個事實（誰做了什麼、哪本書說的、年代、數字、引文）都必須出自你這次**實際抓到並讀過**的網頁。記憶只能用來決定去查哪裡，不能當來源。
- 引用古書原文（加引號的句子）前，要抓到那段原文本身（原典電子版，或可靠現代來源裡的引文）。抓不到原文就不要加引號，改寫成「大英百科說，《某書》記載……」並把來源標給大英百科。
- 查不到可靠來源的說法：不寫。若是很有名、讀者一定會問的說法（例如「年獸」沒有古書出處），就明講「查無古代出處」，並標明是誰這樣說的。
- 各書說法不同時並列，用 `disputed` 欄位或正文裡的 ASCII 對照表，不要自己挑一個當定論。
- 後世才加上去的情節，要說清楚是「哪個朝代、哪本書」才出現的（中華神話特別重要：上古原典、漢代、唐宋、明清小說、民間口傳要分清楚）。
- 來源至少 1 個 `kind: ancient`（古代原典；明清小說、唐傳奇、宋元類書對本站來說也算 ancient，cite 要寫朝代與作者）＋ 1 個 `kind: modern`（維基百科不算）。`url` 要是真的能開的網頁；你抓不到但確定存在的原典頁（例如 ctext.org、theoi.com、zh.wikisource.org 的固定章節網址）可以用，但內容必須已從別處驗證。modern 來源加 `accessed: '2026-11-16'`。
- 過去查證經驗（僅供參考，自己再試）：
  - 希臘羅馬：theoi.com（原典英譯與神祇條目）、perseus.tufts.edu、worldhistory.org、britannica.com、topostext.org。
  - 北歐：gutenberg.org/ebooks/73533（Bellows《詩體埃達》）、voluspa.org 與 germanicmythology.com（Brodeur《散文埃達》）、worldhistory.org；sacred-texts.com 連不到（鏡像 neonvagabond.xyz/mirrors/sacred-texts/ 可試）。北歐卡片絕不可出現牛角頭盔、漫威設定（洛基不是索爾的兄弟）。也可讀 /mnt/project-files/myth-atlas/norse-source-pack-2026-11-16.md（已查核的事實）。
  - 中華：zh.wikisource.org（原典全文）、ctext.org、britannica.com（/topic/…）、worldhistory.org；台灣官方資料可試 religion.moi.gov.tw（全國宗教資訊網）、nrch.culture.tw、故宮 npm.gov.tw。worldhistory.org 的 /Name/ 網址有時只是搜尋頁，要確認是真文章。

### 2. 寫多深

ZL 嫌現在資訊太少。每張新卡的正文（frontmatter 之後）目標 **600–1,200 個中文字**，至少包含：

1. `## 故事`：完整講一遍，分 2–4 個 `###` 小節。
2. 「各書怎麼說」：原典不只一種說法時，用 ``` 圍起來的 ASCII 表或流程圖並列（示意圖寬度 ≤ 34 個全形字，手機才不會破版）。
3. 「後來怎麼變」：從最早的記載到今天形象的演變（哪本書加了什麼）。
4. 「今天在哪裡遇到」：只寫查證過的（節日、廟宇、星期名稱、成語、作品），沒查到就不寫這節。

文字要淺白，國中生讀得懂；台灣用語與台灣通行譯名，繁體中文。

### 3. 格式規則（validate 與測試會擋）

- 正文裡除了標題行與 ``` 區塊以外，**每一行（每一段）都至少要有一個 `[sN]`**，而且 sN 要在 sources 裡。
- 欄位照 `docs/card-fields.md`：`three_lines` 剛好 3 句；神祇類要有 `domains`、`how_to_recognize`；故事卡要有 `panels` 4–6 格（每格 `{text, src}`，**不要寫 image**，圖之後再補）；`era` 用自己體系的；`topics` 只能用 `data/topics.yaml` 的 name（新增了 民間信仰、小說與戲曲、死後世界、節日與習俗）。
- 沒有圖：不要寫 `images`，寫 `few_images: 這張卡還沒有收錄圖片。`
- `family` 裡沒有卡片的人物用 `{name: …}`，並在 `data/names.yaml` 最後面補 `名字: {en: …, orig: …}`（中華的 orig 寫帶聲調拼音）。指到別張卡用 `{id: …}`，id 必須是 main 已有的卡或你這一批的卡；別批的新卡先不要連（在回報裡列出「希望之後補的連結」）。正文的 `[[id|文字]]` 連結同理。
- YAML flow map 裡，cite 或 why 含「: 」「,」「'」「#」或開頭是引號時要整個加引號。中華卡 `name_orig` 寫「漢字 / 拼音」。
- `reality`：真有其人的（關公、媽祖林默、屈原）用「神話裡有歷史影子」或「真實歷史」，並寫 `evidence` 與 `src`。
- **不要動**：別人的卡片、`data/eras.yaml`、`data/topics.yaml`、tests、src。只可新增你這批的卡片檔，並在 `data/names.yaml` 尾端加行。
- 不新增今日影子（之後統一做）。

### 4. 完成前自己檢查

```
npm run validate          # 你的卡 0 錯誤（警告可以）
npm run build:index       # 能產生 site-data.json
```

再自己重讀每張卡一次：每個 [sN] 標的句子，真的是那個來源說的嗎？

然後 `git add` 你的檔案並 `git commit`（訊息：`內容：<批名> 新增 N 張卡`，結尾加
`Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`）。不要 push。

### 5. 回報格式（精簡）

- 完成的卡片 id 與每張正文字數。
- 每張卡用了哪些實際抓到的網址（一行一張）。
- 沒查到、所以沒寫或改寫的內容；你自己不放心的句子。
- 希望之後補的跨批連結。
- 清單裡你認為不該收、或應該補收的卡（附理由）。
